# Maintainer Workflow

This document describes how maintainers interact with the TrustBridge dashboard,
the mutation endpoints they use, and the audit/correlation identifiers returned
by those endpoints for support and traceability.

## Overview

Maintainer mutations (pause/freeze, moderation actions, org-scope changes) are
exposed under `src/app/api/maintainer/`. Every mutating request is recorded via
`src/lib/audit.ts`, which generates a correlation id for the operation.

## Correlation / audit ids

All **mutating** maintainer endpoints now return a correlation id so support can
trace a Wave moderation action end-to-end.

### Success responses

Successful mutations include the correlation id in the JSON body:

```json
{
  "ok": true,
  "correlationId": "aud_01HZX...",
  "auditId": "aud_01HZX..."
}
```

- `correlationId` — the id generated by `src/lib/audit.ts` for this request.
- `auditId` — the persisted audit record id (equal to `correlationId` when the
  audit write succeeds synchronously).

### Error responses

Errors surfaced through `src/lib/error-handling.ts` include the same
`correlationId` in a stable shape so operators can quote it to support:

```json
{
  "ok": false,
  "error": {
    "code": "FORBIDDEN",
    "message": "Insufficient permissions for this organization.",
    "correlationId": "aud_01HZX..."
  }
}
```

- The `correlationId` is always present on mutating endpoints, including auth,
  CSRF, org-scope, pause/freeze, and dry-run failures.
- Read-only endpoints are unchanged and do not emit correlation ids.

### Reason codes

When a mutation is rejected, the error `code` is one of the stable reason codes
documented in `src/lib/error-handling.ts` (e.g. `UNAUTHORIZED`, `FORBIDDEN`,
`CSRF_INVALID`, `ORG_SCOPE_MISMATCH`, `PAUSED`, `FROZEN`, `DRY_RUN_ONLY`,
`INVALID_INPUT`). The `correlationId` accompanies every one of these.

## Preserved semantics

Wiring correlation ids does **not** change existing behavior:

- Auth and CSRF checks run exactly as before; failures still reject the request.
- Org-scope enforcement is unchanged.
- Pause/freeze state is respected; paused/frozen mutations still fail.
- Dry-run requests still perform no privileged writes.
- Happy-path responses keep their existing fields; the correlation id is additive.

## Support workflow

1. Ask the operator for the `correlationId` shown in the UI or error payload.
2. Look up the audit record via `src/lib/audit.ts` using that id.
3. Cross-reference the maintainer action, org scope, and timestamp.

## Testing

Targeted tests cover the happy path plus at least two failure paths
(auth/CSRF rejection and org-scope/pause rejection), asserting that the
`correlationId` is present and stable in each response.

```bash
# Run maintainer API + audit tests
npm test -- src/app/api/maintainer src/lib/audit
```

## Wave operator risk note

Correlation ids are additive and do not alter authorization, pause/freeze, or
dry-run behavior. Operators should expect an extra `correlationId` field in
mutation responses and error payloads; no client changes are required to keep
working, but support tooling can now trace actions by id.
